# 오늘의 말씀 전용 묵상 콘텐츠 가이드

## 1. 목적과 적용 범위

Daily 묵상은 고민을 입력하지 않은 사용자가 말씀을 천천히 읽고, 그 말씀 앞에서 자신의 생각과 삶을 돌아보도록 돕는 콘텐츠다. 성경공부의 정답을 제시하거나 특정 고민을 해결하는 설명문이 되지 않도록 한다.

기존 고민 추천용 reflections.js와 별도로 새로 작성한다. 고민용 원고에서 감정 표현만 삭제해 재사용하지 않는다. 데이터는 dailyReflections[verseId] 아래 reflection과 정확히 3개의 questions로 구성한다. prayer는 현재 범위에 포함하지 않는다.

## 2. 확정 기준 샘플(golden samples)

아래 5개는 사용자가 실제 모바일에서 검수한 최종 기준 샘플이다. 원문 기준은 dist/data/daily-reflections.js의 현재 최종본이며, 가이드를 적용한다는 이유로 다시 수정하지 않는다. 이후 변경에는 별도 검수가 필요하다.

| 말씀 | 실제 ID | 작성 기준으로 살필 특징 |
|---|---|---|
| 요한복음 11:35 | john-11-35 | 예수님의 눈물을 바라봄 → 타인의 눈물 앞에서 자신의 태도를 돌아봄 → 하나님께 마음을 나눌 여지 |
| 시편 139:13–14 | psalm-139-13-14 | 하나님의 지으심 → 생명의 놀라움 → 시편 기자의 감사와 자신의 말 |
| 마태복음 11:28 | matthew-11-28 | 예수님의 초대 → 쉼과 예수님께 배우는 삶 → 하루 안에서 머물 시간 |
| 로마서 8:28 | romans-8-28 | 성령의 도우심과 소망 → 하나님의 뜻과 일하심 → 답을 정하지 않은 질문도 허용 |
| 여호수아 1:9 | joshua-1-9 | 여호수아의 사명 → 하나님의 동행에 근거한 담대함 → 일상의 책임을 돌아봄 |

샘플의 톤과 해석 원칙을 기준으로 삼되, 문장 순서와 질문 구조를 그대로 복제하지 않는다. 특히 세 번째 질문을 모두 기도나 행동 계획으로 끝낼 필요는 없다.

## 3. Reflection의 목적과 흐름

기본 흐름은 다음과 같다.

본문의 장면·고백을 바라봄 → 그 안에서 드러나는 하나님·예수님·말씀의 중심을 살핌 → 오늘 그 말씀 앞에 머물도록 초대

첫 문장은 해당 본문에 발을 딛는다. 마지막 문장은 독자가 자기 속도로 생각할 공간을 남긴다. 모든 구절을 같은 도입과 마무리 문장에 끼워 넣지 않는다. 안내만 읽고 본문을 지나치게 하기보다, 다시 본문을 바라보게 돕는다.

## 4. 본문 문맥과 해석 경계

- 프로젝트의 검증된 말씀 본문과 contextNote를 먼저 확인한다. 본문·출처 자체는 임의로 수정하지 않는다.
- 본래 화자, 청중, 사건과 문학적 성격을 구분한다. 특정 인물에게 주어진 명령이나 약속을 모든 독자의 모든 계획에 바로 적용하지 않는다.
- 필요한 배경만 짧게 담는다. 확인되지 않은 역사적 배경이나 인물의 속마음, 하나님의 숨은 의도를 만들어내지 않는다.
- 자연스러운 적용처럼 보여도 본문에 직접 나타나지 않는 장면이나 의미를 덧붙여 질문의 전제로 만들지 않는다. 본문의 장면을 언급한다면 사용자가 그 장면을 본문에서 실제로 확인할 수 있는지 검토한다.
- 본문에 있는 약속은 그 대상과 문맥 안에서 다룬다. 독자의 성공·회복·관계 복원·원하는 결말을 보장하는 문장으로 확대하지 않는다.
- 고통 자체를 선이나 하나님의 뜻이라고 단정하지 않는다. 하나님이 특정 일을 허락하신 이유를 설명하거나, 고난에서 반드시 교훈을 찾아야 한다고 요구하지 않는다.
- 의학적 판단이나 위험 상황에 대한 안전 조치를 대신하는 적용을 하지 않는다.

말씀별 경계도 유지한다. 요한복음 11:35를 개인의 상실이 되돌려진다는 약속으로, 시편 139편을 외모 만족을 요구하는 자기긍정으로, 마태복음 11:28을 책임의 소멸로, 로마서 8:28을 모든 고통의 긍정으로, 여호수아 1:9를 성공 보장으로 바꾸지 않는다.

## 5. 사용자의 상태를 가정하지 않기

본문 속 인물의 상황과 현재 독자의 상황은 다르다. 예수님이 슬픔을 마주하셨다고 독자가 사별 중이라고 쓰지 않는다. 쉼의 초대가 있다고 독자를 번아웃 상태로, 여호수아의 사명이 있다고 독자를 새로운 출발 앞에 있는 사람으로 설정하지 않는다.

일상·관계·책임을 돌아볼 수는 있지만 특정 사건, 상처, 부족한 믿음이나 감정을 이미 가진 것으로 묻지 않는다. 질문에 답이 바로 떠오르지 않거나 본문과 거리를 느끼는 독자에게도 열려 있어야 한다. 조건형 표현이라도 매번 특정 고민으로 독자를 끌고 가지 않도록 한다.

## 6. 내부 기준을 사용자 경고문으로 쓰지 않기

오해 방지 원칙은 작성과 검수 단계에서 엄격히 적용한다. 사용자 reflection에는 “이렇게 해석하면 안 됩니다”, “성공을 보장하는 뜻이 아닙니다” 같은 규칙 설명을 반복하지 않는다.

대신 문장의 초점과 범위를 본문 안에 둔다. 여호수아에게 주어진 약속은 여호수아의 장면에서 설명하고, 로마서의 고백은 성령의 도우심과 소망의 흐름 안에서 쓴다. 경고문을 뺀 뒤에도 과장된 적용이 남아 있지 않은지 확인한다.

## 7. 질문 3개의 역할과 다양성

질문은 서로 다른 세 가지 생각의 공간을 만든다. 활용할 수 있는 각도는 본문을 천천히 바라보기, 평소의 생각과 태도 돌아보기, 관계나 일상에 연결하기, 감사·질문·소망을 자신의 말로 표현하기 등이다. 아래 기준은 Daily 묵상 20개의 실제 모바일 사용자 검수에서 확정한 원칙이다.

- 정확히 3개를 쓰되, 본문 → 나 자신 → 하나님이나 관찰 → 적용 → 기도 같은 고정 구조를 의무화하지 않는다. 본문의 성격에 따라 세 질문의 역할을 정한다.
- 한 질문에는 중심 과제를 하나만 둔다. 설명, 감정 확인, 행동 계획을 한꺼번에 요구하지 않는다.
- **세 질문이 서로 다른 답을 떠올릴 수 있게 하는지** 확인한다. 표현만 다르고 사실상 같은 답을 요구하는 질문은 다듬는다. 독자에게 서로 다른 답을 반드시 쓰라고 요구하는 기준은 아니다.
- “본문에서 이유를 찾으세요”, “명령과 약속의 관계를 설명하세요” 같은 정답형·시험형 질문을 피한다.
- “어떤 표현이 남나요 / 어떤 생각이 드나요 / 하나님께 무엇을 말할까요”를 모든 구절에 반복하지 않는다.
- 인접 원고끼리 질문의 시작말·핵심 동사·응답 방식·마무리를 비교한다. 표현이 같지 않아도 실제 묻는 내용이 반복되면 다시 살핀다.
- 세 번째 질문이라고 반드시 행동 계획이나 관계 적용으로 넘어가지 않는다. 본문 자체를 더 바라보는 것이 적절하면 그 자리에서 묵상을 마쳐도 된다. 적용이나 다양성을 만들기 위해 본문에서 멀어지지 않는다.
- 본문이 매우 짧아 관찰할 내용이 하나뿐이라면 “가장 마음에 남는 부분은 무엇인가요?” 같은 형식적 관찰 질문을 억지로 만들지 않는다. 질문 수를 채우기보다 실제 묵상에 도움이 되는 질문을 만든다.

### 질문을 쉬운 말로 쓰는 기준

- 질문을 **한 번 읽고 무엇을 생각하거나 답하면 되는지 바로 알 수 있는지** 검수한다. “그래서 무엇을 생각하라는 거지?”라고 느낄 만한 표현은 다시 다듬는다. 신학적으로 맞더라도 문장의 뜻을 해석해야 답할 수 있다면 좋은 질문으로 보지 않는다.
- 질문의 방향과 의미가 본문에 잘 맞는다면, 다른 질문으로 교체하기 전에 같은 의미를 쉬운 일상어로 풀 수 있는지 먼저 검토한다. **의미는 보존하고 표현만 쉽게 만드는 것을 우선**하며, 본문과의 연결까지 단순화하지 않는다.
- 예: “일상의 책임을 마주할 때, 하나님의 동행을 기억하는 것은…” → “내가 해야 할 일을 앞두고 있을 때, 하나님이 함께하신다는 것을 기억하면…”
- “어떻게 다가오나요?”, “어떤 의미인가요?”, “무엇을 새롭게 보게 하나요?”, “어떤 반응이 일어나나요?”, “삶의 방향”, “말씀 곁에 놓다”, “시선에 무엇이 더해지다”, “동행을 기억하다”를 습관적으로 사용하지 않는다. **표현 자체를 금지하지는 않으며**, 해당 본문에서 자연스럽고 사용자가 바로 이해할 수 있을 때만 사용한다.
- 동행·시선·머무름·반응·삶의 방향 같은 추상적인 표현이 여러 개 겹치면 구체적이고 일상적인 말로 풀어 쓴다.
- 예쁜 문장보다 쉬운 문장을 우선한다. 문학적이고 감성적인 표현이 앱 분위기에 어울려도 의미를 해석해야 한다면 더 쉬운 표현을 선택한다. 사용자는 질문 문장을 이해하는 데 생각을 쓰는 것이 아니라 **말씀을 묵상하는 데 생각을 쓸 수 있어야 한다.**

## 8. 하나님께 이야기하도록 초대하는 방식

감사, 질문, 침묵, 아직 정리되지 않은 마음을 허용한다. 감사나 확신을 이미 갖고 있다고 전제하지 않으며, 정해진 신앙적 결론에 도달해야 기록할 수 있게 만들지 않는다.

“나누고 싶은 이야기가 있나요?”, “지금 떠오르는 말로 시작해보세요”처럼 선택의 여지를 둔다. 반드시 기도문을 쓰거나 결단하고 감사해야 한다고 요구하지 않는다. 모든 원고에 이러한 초대를 넣을 필요도 없다.

## 9. 모바일 가독성과 길이

- reflection은 현재 기준 샘플처럼 약 4문장, 한 문단을 우선 출발점으로 삼는다. 이는 편집 참고값이며 합격 글자 수가 아니다.
- 배경 설명은 핵심을 이해하는 데 필요한 만큼만 쓴다. 같은 의미를 반복하거나 의미 없이 문장을 늘이지 않는다.
- 질문은 가능하면 한 문장으로 쓴다. 짧은 초대와 질문, 또는 답을 돕는 배려가 꼭 필요하면 두 문장도 허용한다.
- 질문 하나에 설명과 질문을 과도하게 겹쳐 넣지 않는다. 긴 관형절이나 여러 추상어가 이어지면 자연스러운 말로 풀어 쓴다.
- 모바일에서 지나치게 긴 여러 줄이 되지 않도록 검토하되, 글자 수나 줄 수를 맞추려고 본문의 의미와 필요한 맥락을 생략하지 않는다.
- 짧게 만드는 것 자체보다 한 번 읽고 이해할 수 있는 자연스러운 문장을 우선한다. 모바일에서도 질문이 무엇을 묻는지 즉시 알 수 있는지 확인하고, 이해하기 어렵다면 7번의 쉬운 말 기준으로 의미를 보존하며 다듬는다.
- 390px·319px와 글씨 크기 설정에서 실제로 읽어본다. 정상적인 줄바꿈과 세로 스크롤은 허용하고, 글씨를 축소해 원고를 맞추지 않는다.

## 10. 문체·존댓말·어미

- 차분하고 따뜻한 해요체를 기본으로 한다. 설명은 “말씀하세요”, “담겨 있어요”, 초대는 “바라보세요”, “생각해보세요”, 질문은 “있나요?”, “될까요?”처럼 쓴다.
- 같은 문단에서 해요체와 “~합니다”, “~하라”를 불필요하게 섞지 않는다. 성경 본문의 직접 인용은 원문을 존중한다.
- 안내에서는 “예수님”, “하나님”, “주님” 등 샘플의 호칭과 높임을 유지한다. 질문의 자기 성찰에는 “나”, “내”를 자연스럽게 사용한다.
- 따뜻함을 위해 과장된 위로나 친밀감을 덧붙이지 않는다. 독자의 마음을 다 안다는 듯 말하지 않는다.
- 같은 어미를 기계적으로 반복하지 않되, 변화를 위해 말투를 바꾸지는 않는다. “천천히”, “조용히”, “머물러보세요”도 모든 문장에 장식처럼 붙이지 않는다.

## 11. 피할 표현과 좋은 표현의 예시

아래 좋은 표현은 현재 golden samples에서 가져왔다. 다른 말씀에 그대로 붙이는 공용 문구가 아니다.

| 피할 표현 | 문제 | 좋은 표현 |
|---|---|---|
| “지금 사랑하는 사람을 잃어 슬프시지요.” | 독자의 상황·감정 단정 | “나사로의 죽음 앞에서 예수님은 눈물을 흘리셨어요.” |
| “그러니 자신의 외모를 사랑해야 해요.” | 자기긍정으로 축소·감정 요구 | “시편 기자는 자신을 모태에서 지으신 하나님을 바라보아요.” |
| “현실의 모든 책임이 사라진다는 뜻은 아니에요.” | 내부 경계를 해설식 주의사항으로 노출 | “그 초대는 이어지는 말씀에서 예수님께 배우며 함께 걷는 삶으로 펼쳐져요.” |

## 12. 작성·검수 순서

1. 말씀 본문과 contextNote를 읽고, 중심 장면·고백과 해석 경계를 내부 메모로 정리한다.
2. 그 중심에서 reflection을 새로 쓴다. 사용자의 고민을 먼저 설정하지 않는다.
3. 서로 다른 각도의 질문 3개를 작성한다. 정답을 유도하거나 같은 답을 반복해서 요구하지 않는지 본다.
4. 감정 가정, 결과 보장, 고난의 의도 단정, 신앙 평가, 경고문 노출을 검토한다.
5. golden samples 및 주변 원고와 비교해 문체·길이·질문 중복을 살핀다.
6. LAN Preview에서 모바일 가독성과 한 번 읽고 질문을 이해할 수 있는지 확인하고 사용자의 콘텐츠 검수를 받는다.
7. 실제 verse ID, 비어 있지 않은 reflection, 정확히 3개의 질문, 빈 질문·항목 내 중복 질문·완전 중복 reflection을 계약 테스트로 확인한다. 의미·신학·질문 다양성은 사람이 별도로 검토한다.

기존 concern 데이터와 개인 기록 구조는 유지한다. 콘텐츠 승인과 별도의 전환 지시 전에는 production에 연결하지 않는다. 현재 단계에서는 확정된 5개를 기준으로 가이드만 정리하며, 나머지 95개 작성은 시작하지 않는다.
